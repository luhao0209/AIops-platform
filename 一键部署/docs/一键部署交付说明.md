# AIOps 一键部署交付说明

## 1. 文件说明

压缩包解压后结构如下：

```text
一键部署/
├── aiops-installer-20260901.1-linux-amd64.run
├── deployment.env.example
├── images/
│   ├── image-bundle.json
│   ├── business-images.tar
│   └── agent-images.tar
├── docs/
│   └── 一键部署交付说明.md
├── 交付清单.json
└── SHA256SUMS
```

`.run` 内含项目源码、部署脚本、Ansible Playbook、Kubernetes 清单、固定 vendor 清单和评测器。`images/` 内含当前版本的 6 个 Linux amd64 应用镜像：

- `aiops-gateway:20260830-5`
- `aiops-agent:v6`
- `aiops-agent-executor:v112`
- `aiops-inspection-engine:v2`
- `aiops-change-watcher:v2`
- `aiops-sop-service:v4`

安装器会验证两个镜像归档的大小、SHA-256 和归档内部 OCI 镜像标签，之后只导入到实际调度这些应用的 worker-biz、worker-ai 节点，不再现场构建应用镜像。

## 2. 网络依赖

应用镜像和项目文件已经包含在交付包中，但系统软件包和第三方基础镜像仍需联网下载。这不是完全断网安装包。

已经随包携带：

- 六个应用镜像及镜像内 Python 依赖。
- SOP 服务使用的本地 BGE 模型权重。
- 项目源码、部署工具、Kubernetes 配置和固定 Calico/local-path manifest。
- 文件级与包级校验信息。

部署时仍需联网获取：

- Ubuntu/Debian 系统包和 Kubernetes/containerd 组件。
- Calico、Prometheus、Grafana、MySQL、Redis、Loki、Qdrant 等第三方基础镜像。
- 控制机的固定 Ansible/Paramiko 工具环境。

安装器默认使用国内镜像源。完全断网的环境还需要额外准备 deb、wheel 和第三方 OCI 镜像，本交付包不覆盖这种场景。

## 3. 机器准备

准备一台 Linux amd64 控制机和四台 Ubuntu/Debian amd64 服务器。控制机可以是四台中的 master，也可以是能 SSH 到四台机器的独立机器。

四台目标机要求：

- 至少 2 vCPU、3.4 GiB 可见内存、根目录 15 GiB 可用空间。
- 公网 SSH 可达，节点私网 IP 已配置到网卡且相互连通。
- SSH 用户为 root，或拥有 sudo 权限；非 root 时当前 SSH 密码同时用作 sudo 密码。
- 全新安装，或确认为本安装器此前创建的同一四节点集群。
- 不要在已有其他业务 Kubernetes 集群、半初始化节点或有未知数据的机器上直接执行。

控制机要求：apt 系 Linux amd64、Python 3.11+、bash、tar、curl、awk、tail 和 SHA-256 工具，并能访问项目配置的国内镜像源。缺少 `python3-venv` 时安装器会以 root 或免密 sudo 自动安装；否则需先人工安装该包。

## 4. 第一次使用

进入解压目录：

```bash
cd 一键部署
chmod +x aiops-installer-20260901.1-linux-amd64.run
./aiops-installer-20260901.1-linux-amd64.run --verify-only
./aiops-installer-20260901.1-linux-amd64.run --init-config
```

安装器会在当前目录生成权限为 `0600` 的 `deployment.env`。至少填写：

- 四台机器的 `*_PUBLIC_IP`、`*_PRIVATE_IP`、`*_SSH_PASSWORD`。
- SSH 用户/端口不是 root/22 时填写相应 `*_SSH_USER`、`*_SSH_PORT`。
- `MODEL_API_BASE`、`MODEL_API_KEY`、`MODEL_NAME`。
- `AIOPS_ADMIN_USERNAME`、`AIOPS_ADMIN_PASSWORD`；密码也可留空自动生成。
- `CONFIRM_FRESH_SERVERS=YES`。

模型地址必须是 OpenAI Chat Completions 兼容前缀，不能带 `/chat/completions`，也不能使用 Anthropic Messages 地址。智谱普通平台示例：

```text
MODEL_API_BASE=https://open.bigmodel.cn/api/paas/v4
MODEL_NAME=glm-5.3
```

配置完成后执行：

```bash
chmod 600 deployment.env
./aiops-installer-20260901.1-linux-amd64.run --check-config
./aiops-installer-20260901.1-linux-amd64.run --preflight-only
./aiops-installer-20260901.1-linux-amd64.run
```

如果压缩包直接上传并运行在 master 上，云网络通常不允许 master 通过自己的 EIP 回连四台服务器，应改用私网 SSH：

```bash
./aiops-installer-20260901.1-linux-amd64.run --preflight-only --ssh-private
./aiops-installer-20260901.1-linux-amd64.run --ssh-private
```

`--ssh-private` 只改变 Ansible 连接目标，部署完成后展示的 Web/Grafana/业务访问地址仍使用配置中的公网 IP。独立外部控制机默认不加该参数，继续使用公网 SSH。

不要移动 `.run` 而把 `images/` 留在原目录。安装器只在同级 `images/image-bundle.json` 存在且完整校验通过时使用预构建镜像；否则会退回目标节点现场构建。

## 5. 安装过程

安装器按以下顺序执行，某一步失败就会停止：

1. 在任何远程变更前校验全部配置。
2. 在安装目录的隔离工具环境中准备固定 Ansible/Paramiko/kubectl。
3. 首次生成并持久化运行密钥；重跑只校验，不覆盖。
4. 只读预检四台服务器，随后安装/续跑 Kubernetes、Calico、StorageClass 和节点标签。
5. 校验并导入随包的六个 amd64 应用镜像到 worker-biz、worker-ai。
6. 渲染 Secret、准备 HostPath、部署业务/监控/Agent 工作负载；首次 seed 有数据库空表保护。
7. 验证四节点、Pod、模型请求、Prometheus targets/规则、RAG、Qdrant 和关键服务接口。

部署成功后输出 Web、业务 API、Grafana 地址和 Web 用户名，但不会打印 SSH 密码、模型 Key 或自动生成的运行密码。

## 6. 密钥、数据和重跑规则

- `deployment.env`、安装器 state 内的 `runtime.env` 均必须为普通文件且权限不宽于 `0600`。
- 安装包和 ZIP 不包含任何 `.secrets`、私钥、API Key、密码、SQLite 历史库或评测报告。
- 不要删除 `.aiops-installer-state/<版本>/runtime.env`；它保存数据库、Qdrant、Grafana、Web session 等首次生成的密钥。
- 同一安装包、同一四台机器、同一集群可以在失败修复后重跑。
- 安装器不会自动执行 `kubeadm reset`，不会删除 Namespace、PVC、数据库或已失败 Job。
- seed Job 会重建受管业务表；只有 Job 不存在且三个受管表确认为空时才允许首次执行。任何查询失败或已有表都会停止。
- 该入口是“全新安装或同目标续跑器”，不是任意版本的通用在线升级器。

## 7. 校验交付包

解压后可先执行：

```bash
sha256sum -c SHA256SUMS
python3 - <<'PY'
import json
from pathlib import Path
manifest = json.loads(Path('交付清单.json').read_text())
print(manifest['version'], manifest['application_image_count'], manifest['air_gapped'])
PY
./aiops-installer-20260901.1-linux-amd64.run --verify-only
```

注意：`SHA256SUMS` 中的路径包含顶层交付目录。若已进入该目录，可在其上一级执行 `sha256sum -c 一键部署/SHA256SUMS`，或按实际解压路径调整。

## 8. 已验证范围

当前交付包做过以下验证：

- 本地：Shell/Python 语法、部署单测、安装包篡改防护、镜像清单/OCI 标签和 ZIP 完整性。
- 集群：把预构建镜像重新导入对应节点，确认固定标签存在且运行 Pod 不重启。
- 一键流程：在当前四节点、当前持久化密钥和数据不变的前提下执行一次完整安全续跑，并通过部署后的服务验收。

安装器已在现有四节点集群上完成安全续跑，镜像导入、配置渲染、工作负载更新和接口验收均能正常执行。目前没有在另一套全新的四节点机器上复测首次安装，这一点不应视为已经验证。
